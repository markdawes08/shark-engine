# Physics inspection and debug visualization

20d extends the existing [shared physics preview](physics-preview.md) under [ADR 0056](architecture/0056-physics-debug-inspection.md). Both terminal and Editor use the same retained project, frozen runtime Scene and creating-thread PhysicsWorld. These are local development observations; no player, client renderer or observation gains server gameplay authority.

## Terminal observations

With an active preview, `scene.physics` accepts `raycast`, `overlap_sphere` and `overlap_box`. Each requires the current `session_id`, decimal `expected_tick` and decimal `expected_sequence` (the next operation sequence), `layer`, `mask` and Boolean `include_triggers`. The ray has three-number `from` and `to`; the sphere has `center` and `radius`; the axis-aligned box has `center` and `half_extents`. Optional `ignore_entity_id` resolves a current body in this session; optional `max_hits` is 1..128, default 64. Core's [query contract](physics-queries.md) defines bounds, bilateral filtering, geometry and sorted complete-or-error results.

Results return the same session, tick and next sequence with owned `entity_id` and `is_trigger` per hit. Ray hits also provide `fraction`, three-number `position`, and `normal` as a vector or null for fraction-zero hits. Native handles and global world positions are not exposed. Inputs, owner, session, tick, sequence and ignored body are checked each call. A same-tick body removal advances the operation sequence, so stale observations reject even when the tick still matches. Ordinary successful inspection does not step, consume contacts or change Scene/history/operation sequence.

The existing paginated `query` remains compatible. `bodies_only: true` additionally requires `expected_sequence` and returns only checked active bodies in stable entity order; each row adds `physics_body` with committed native `pose`, `collider_half_extents` and dynamic `velocity` (null for non-dynamic bodies). Native extents already include uniform body scale. The preview admits at most 128 bodies and pages at most 128 rows. All results are historical observations; resolve fresh values for later work. A failed native consistency check can fault the physics owner under the original Core contract.

## Editor

During an active preview, the Physics inspection controls offer a collider overlay, a runtime body list, and a paused ray/sphere/box query using the same service, filters, optional selected-body exclusion and hit limit. The list reports identity, motion, shape, trigger and layer/mask, committed position, rotation and scale, and velocity where available. Ray details include the hit position and normal (or an explicit unavailable normal). The overlay draws static bodies gray, dynamic cyan, kinematic blue, triggers orange, query geometry yellow and ray hit marks pink. It is clipped to the actual viewport and uses its camera and origin. Lines approximate the primitive surfaces with box edges and 24-segment rings at committed native poses, which can differ from the interpolated scene image. Lines are display-only, are not depth-tested against scene meshes and do not authorize picking or edits.

Query results and geometry belong to the observed session/tick/sequence and are cleared on a subsequent step, removal, restart or stop. The CPU geometry is bounded; invalid inputs produce an error rather than a partial result. The viewport emits at most 2,048 clipped lines, prioritizing query geometry and hits, and explicitly warns if collider outlines are truncated. Terminal body and spatial observations retain their complete-or-error behavior. Existing preview reconciliation, pause/step, source isolation and teardown remain unchanged. Debug display and query operations do not create a second Scene, world, scheduler, native debug renderer, source format or public player protocol.
